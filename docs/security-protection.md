# 账号与 IP 滥用防护

本模块把新账号签到、同来源账号聚集、受限后重复尝试和注册提交频率组合起来，提供可观察、可配置、可撤销的处置。它不判断现实身份，不以共享 IP 单独认定同一人，也不替代账号认证、模型发布权限、计费、反向代理或防火墙。

本文描述对应源码的行为与默认值，不包含部署实例的账号、IP 名单、运行配置或调查资料。

## 管理入口与权限

超级管理员可在 `/security-protection` 查看健康摘要、配置、检测事件和限制记录。普通用户和普通管理员没有此页面的管理权限；服务端对 `/api/security-protection` 的所有接口执行根管理员鉴权，写接口还保留同源校验、频率限制和操作审计。前端隐藏菜单不是授权边界。

页面复用现有认证会话，不要求另外输入或保存管理员密码、API Key 或模型密钥。管理权限失效后，页面隐藏已读取的数据、停止轮询并清理本用户的防护查询缓存。

## 开关与动作的含义

初次创建配置时，`enabled=false`、`mode=observe`。初始化不会自行开启签到，也不会改变注册提供方的开关。

| 状态或动作 | 实际行为 |
| --- | --- |
| 自动总开关关闭 | 不执行自动行为阈值规则；已有自动限制记录不删除，但暂停执行。 |
| `observe`：只观察 | 记录自动规则的命中与数值证据，不因这些规则新增自动限制或拒绝正常领奖。已有自动限制暂停执行。 |
| `enforce`：执行防护 | 总开关同时开启时，按规则暂缓领奖、暂缓过量注册，并在更高组合阈值达到时临时限制精确 IP。 |
| 暂缓领奖，`scope=checkin` | 只限制签到领取，不改变账号原生状态，不限制该账号正常的模型请求。 |
| 账号限制，`scope=account` | 限制目标账号的登录及经过现有身份认证的业务请求。 |
| IP 限制，`scope=ip` | 限制应用层看到的精确来源 IP，不创建网段封禁。后端模块本身不直接改外部配置；部署可由独立受控同步服务将有效的精确 IP 限制同步到网站入口。 |
| 暂缓注册，`scope=registration` | 限制当前来源的过量新注册提交，不因注册频率直接停用已有账号。 |

**人工限制独立于自动总开关和模式。** 关闭自动防护或切换到观察模式，不撤销人工限制、原生停用/删除状态或外部网站封禁。人工限制必须按记录撤销或等待到期。白名单也不会恢复原生已停用或已删除的账号。

“只观察”只针对自动行为规则。原生账号校验、人工限制、签到来源不可确认时不入账，以及存储故障时停止发放奖励的护栏仍然有效。

限制记录的有效期与自动规则当前是否启用是两个概念：一条自动记录可以尚未到期，同时因总开关关闭或观察模式而暂停执行。

## 自动检测规则

### 签到

新账号由 `new_account_age_seconds` 认定，默认账号年龄小于七天。首次历史签到另有注册后冷静期，默认一小时；已有历史签到的账号不重复经历“首次”冷静期。

同 IP 每日新账号签到上限统计新账号在当天的成功领取。认定窗口内的账号在后续日期再次签到，仍参与当天计数，并非只统计该账号的首次历史领取。日期沿用签到服务使用的服务端日期口径。

短时聚集规则同时检查不同的新 UID 数量和注册后快速领奖的新 UID 数量。一个 UID 重复尝试不会放大“不同账号数”。命中后可以只给当前账号添加临时 `checkin` 限制。

自动 IP 限制需要更高的组合证据：窗口内新 UID 数达到阈值，且已受限后继续重试的次数达到阈值。普通的首次受限尝试不直接等同于持续重试。自动动作会记录策略修订、请求 ID、计数和阈值。

签到防护、签到记录、来源领取事实和余额增量位于同一数据库事务中，并按精确 IP 与 UID 顺序加锁。并发请求继续受同 UID 每日唯一约束。被拒绝的决定及必要限制可以留存，但不会发放奖励；事务写入失败也不会先发额度后补记录。

### 注册

注册检测窗口内的提交次数超过配置上限时，执行模式只暂缓新注册提交，返回可重试提示。观察模式只记录命中。已存在 OAuth 身份的正常登录不会按新账号创建处理；实际新建账号仍经过注册保护。

`registration_ip_hour_limit` 是历史字段名，实际统计窗口由 `registration_window_seconds` 决定，不应把字段名理解为始终固定一小时。

### 共享出口与来源可信度

自动注册/IP 限制会检查该来源在相关窗口内是否关联正常老账号、管理员、明确的用户白名单，或有已验证成功外部支付的账号。有此类关联时，跳过可能牵连整个共享出口的自动处置。消费赠额、站内余额转移和未完成订单不作为已付款证明；经复核的特殊授予可使用明确的 UID 白名单。

这项共享出口保护不把该 IP 上的所有新账号变成白名单，也不免除每个新账号自己的签到规则或既有人工限制。关联来自当前留存的活动和事件，只能降低误伤，不能证明现实身份或保证没有遗漏。

IPv6 `/64` 前缀仅作关联证据，限制始终落在精确地址上。客户端 IP 由服务器经过受信任代理配置的 `ClientIP` 提供，不能直接相信任意客户端提交的转发头。部署者应使应用入口与代理信任范围相符。普通用户的来源缺失或属于非公网地址时，签到返回 `security_source_unavailable` 且不入账，不因此自动封禁付费 API。管理员和明确白名单只豁免本模块允许豁免的检查。

## 配置与版本

配置保存在独立、带修订号的防护配置表中，不通过通用选项接口绕过修订检查。保存必须同时提交 `expected_revision` 和完整配置；其他管理员已修改时返回 HTTP 409 / `security_revision_conflict`。页面保留未保存草稿，须明确载入最新版本后再调整，不自动覆盖他人修改。

| 字段 | 源码默认值 | 允许范围或说明 |
| --- | ---: | --- |
| `first_checkin_cooldown_seconds` | 3600 | 0–604800；不能大于新账号认定窗口。 |
| `new_account_age_seconds` | 604800 | 3600–2592000。 |
| `ip_daily_new_user_limit` | 5 | 1–1000，每 IP 每日新账号签到上限。 |
| `burst_window_seconds` | 600 | 60–3600。 |
| `burst_new_user_threshold` | 6 | 2–1000。 |
| `burst_rapid_user_threshold` | 3 | 2 至聚集新账号阈值。 |
| `rapid_claim_seconds` | 60 | 1–3600。 |
| `auto_ip_window_seconds` | 3600 | 600–86400。 |
| `auto_ip_new_user_threshold` | 20 | 10–10000。 |
| `auto_ip_denied_threshold` | 10 | 5–10000，受限后重试计数阈值。 |
| `auto_ip_ban_seconds` | 900 | 60–86400，自动限制最长一天。 |
| `registration_ip_hour_limit` | 20 | 10–10000。 |
| `registration_window_seconds` | 3600 | 600–86400。 |
| `retention_days` | 30 | 7–180，普通事件与活动关联保留窗口。 |
| `allowlist_ips` / `allowlist_user_ids` | 空 | 每类至多 200 项；用户 ID 为正整数。 |

管理页面只新增精确 IP 白名单，保留服务器已有的合法白名单网段。管理 API 可接受受限的白名单 CIDR，但拒绝全网段与映射 IPv6 网段。白名单应按复核需要配置，不能用扩大白名单代替修复代理来源。

## 人工处置、到期与撤销

控制台默认选择“暂缓领奖”，提供 15 分钟、1 小时、24 小时或 7 天的临时限制。提交前会展示目标、范围、时长和原因。自动规则不删除账号，也不创建永久封禁；控制台没有永久封禁或删除账号入口。管理 API 为显式人工操作保留更长时长及永久记录能力，这不属于自动默认行为。

服务端拒绝限制当前管理员、其他管理员、已原生停用/删除的用户或明确白名单用户。IP 限制只能是单个公网地址，不能是 CIDR、私网、当前操作来源、白名单地址或已观测的管理员来源。前端校验只用于提前反馈，最终校验由服务端完成。

到期状态在每次访问检查时按服务端当前时间即时判断，不依赖清理任务及时运行。撤销必须指定限制记录 ID 和原因，并记录操作者、时间及请求 ID；只影响该记录，不修改余额、不删除使用证据，也不解除其他来源的限制。

普通受限响应包含可读提示、规则标识和错误码；有明确剩余时间时包含 `retry_after` / `Retry-After`。签到/注册的自动拒绝通常为 HTTP 429，访问限制为 HTTP 403。客户端应展示提示和重试时间，不循环高速重试。

## 隐私、留存与健康摘要

模块记录 UID、规范化来源 IP、必要 IPv6 关联前缀、路由模板、时间、规则、决定、请求 ID、策略修订与数值证据。它不采集聊天正文、模型输入输出、密码、账号令牌、模型密钥、请求正文、查询参数或任意请求头。操作者填写原因时也不应粘贴这些内容。

普通事件和活动关联按 `retention_days` 清理。自动 IP 处置事件至少保留 90 天；人工限制/撤销审计、限制记录和成功签到事实不会因普通事件保留窗口到期而一并删除。清理由主节点周期任务执行，不能把保留期限误解为所有相关记录都自动删除的承诺。

健康摘要确认主数据库中的配置和防护/计数相关表可读，不依赖 Redis。它不是数据库灾难恢复、外部支付真实性或整站安全性的完整检查。事件页面只展开允许的数值证据字段，不把原始响应对象直接展示给用户。

## 故障行为与恢复签到次序

| 情况 | 本模块的处理 |
| --- | --- |
| 初始化建表或配置初始化失败 | 服务启动失败并报告初始化错误，不伪装为防护已就绪。 |
| 运行中防护数据库不可读或写入失败 | 签到不入账；注册保护暂不可用时不继续创建账号。 |
| 普通登录/业务请求无法读取防护状态 | 本模块不因这次存储错误增加全站封禁；请求继续接受既有认证、账号状态、模型发布权限和计费检查。此时防护层的动态禁令可能不能即时执行。 |
| 控制台配置保存失败或版本冲突 | 保留页面修改并显示失败，不显示为已保存，不自动重放覆盖。 |
| 客户端已建立 WebSocket | 后续 `response.create` 重新检查账号/IP 限制，并继续检查模型发布权限；已完成升级不等于持续授权。 |

建议按以下次序恢复签到，不能把打开签到开关当成防护验收本身：

1. 备份数据库和配置，确认建表完成、可信来源 IP 正确、健康摘要可读，已有原生停用与外部封禁保持。
2. 保持签到关闭完成配置和测试。可用隔离测试环境验证观察模式记录、执行模式拒绝、并发不重复入账、管理员/共享出口保护、到期和撤销、存储故障不发额度，以及既有模型权限仍有效。
3. 保存预期阈值与白名单，确认服务端返回的新修订号；启用自动总开关和执行模式，读取回验。
4. 防护验收通过后，单独开启签到功能；这一步不需要重新开启任何已关闭的第三方登录/注册提供方。
5. 核对首批真实签到和账目、拒绝原因及误伤反馈。需要回退自动处置时切为观察或关闭总开关，并单独复核需要撤销的人工记录；不要回退数据库到丢失限制或账目事实的旧快照。

## 构建与对应源码

本仓库前端提供 `frontend/web/bun.lock`，应使用冻结锁文件安装依赖，避免未审查的新版本改变构建。Node.js 和 Bun 环境应与构建记录一致；后端需要 `go.mod` 声明的 Go 版本或兼容版本。

在干净的源码检出目录中，典型构建顺序为：

```sh
cd frontend/web
bun install --frozen-lockfile --ignore-scripts
bun run typecheck
bun run build
cd ../..
mkdir -p backend/web/dist
cp -a frontend/web/dist/. backend/web/dist/
cd backend
CGO_ENABLED=0 go build -trimpath -o new-api .
```

`backend/main.go` 通过 `go:embed` 嵌入完整 `web/dist` 及其 `index.html`。必须先复制经验证的完整前端构建结果，不能只提供占位 HTML。两个 `dist` 都是构建输出，不应混入源码归档或提交到 Git。数据库、运行配置、日志、密钥、私有证据和部署备份同样不属于对应源码包。

前端单独部署时，新增带内容哈希的静态资源应先上传，HTML 入口最后切换。应继续保留仍被缓存入口引用的旧哈希资源，以及部署者原有的静态页面、下载资源和路由；不要用清空线上目录的方式覆盖。发布工具应在部署前列出变更文件并核验，部署后检查入口引用和关键旧地址。

实现入口：[后端规则与事务](../backend/model/security_protection.go)、[管理与留存](../backend/model/security_protection_admin.go)、[管理路由](../backend/router/security_protection.go)、[控制台](../frontend/web/src/features/security-protection/index.tsx)。阈值与组合规则只能降低已覆盖模式的滥用风险，不能保证消除所有批量账号、代理轮换、合法账号被接管或误拦截；仍需按事件、账目与用户反馈持续复核。
